## 二、Bug 清单

### 🔴 严重（Security / Data Loss）

#### BUG-001：管理员页面无任何认证保护

**位置**：[src/app/admin/articles/page.tsx](src/app/admin/articles/page.tsx)、[src/app/admin/videos/page.tsx](src/app/admin/videos/page.tsx)

**问题**：`/admin/articles` 和 `/admin/videos` 是公开可访问的页面，任何人都可以创建、编辑、删除文章和视频。这两个页面虽然使用了 `'use client'` 组件，但根本没有检查用户是否登录或是否为管理员角色。

**影响**：任何知道这两个 URL 的人都可以修改网站内容，甚至删除所有文章。

**修复建议**：在页面顶部添加登录状态检查，未登录则重定向到首页或显示登录弹窗。API 路由也需要添加认证中间件。

---

#### BUG-002：文章删除 API 无路径遍历防护

**位置**：[src/app/api/articles/route.ts:199](src/app/api/articles/route.ts)

**问题**：
```typescript
const slug = searchParams.get('slug')
const filePath = path.join(ARTICLES_DIR, `${slug}.md`)
if (fs.existsSync(filePath)) {
  fs.unlinkSync(filePath)
}
```
`slug` 参数未做任何校验。攻击者可以传入 `../data/users` 来删除数据库文件，或 `../../.env.local` 来删除环境配置。

**对比**：视频删除 API（[src/app/api/videos/route.ts:55](src/app/api/videos/route.ts)）有正则校验 `!/^[a-z0-9][a-z0-9\-]*$/.test(slug)`，但文章 API 没有。

**影响**：可能导致任意文件删除、数据库丢失。

**修复建议**：添加与视频 API 相同的 slug 格式校验，并额外检查最终路径是否在 `ARTICLES_DIR` 范围内。

---

#### BUG-003：文章详情页存在 XSS 注入风险

**位置**：[src/app/insights/[slug]/page.tsx:54-67](src/app/insights/[slug]/page.tsx)

**问题**：
```tsx
dangerouslySetInnerHTML={{
  __html: article.content
    .replace(/^### (.*)$/gm, '<h3>...</h3>')
    .replace(/\*\*(.*?)\*\*/g, '<strong>$1</strong>')
    // ... more regex replacements
}}
```
文章内容是 Markdown → HTML 通过正则手动转换，**没有经过任何 HTML 清洗**。如果文章内容中包含 `<script>`、`<iframe>`、`onerror=`、`javascript:` 等，会被原样输出到页面并执行。

**攻击面**：管理员在后台上传一篇包含恶意脚本的文章内容 → 所有访问该文章的用户被 XSS 攻击。

**修复建议**：
1. 使用专业的 Markdown 转 HTML 库（如 `marked` + `DOMPurify`）
2. 或者至少用 `DOMPurify.sanitize()` 过滤 `dangerouslySetInnerHTML` 的内容

### 🟡 中等（Runtime / Logic）

#### BUG-004：CXRAnalyzer 轮询未清理，存在内存泄漏

**位置**：[src/components/features/CXRAnalyzer.tsx:44-66](src/components/features/CXRAnalyzer.tsx)

**问题**：
```typescript
const pollStatus = async (id: string) => {
  const interval = setInterval(async () => {
    // polling logic...
  }, 2000)
}
```
`setInterval` 创建的定时器在组件卸载时不会自动清除。如果用户在上传分析过程中导航到其他页面，定时器会继续运行，导致：
- 内存泄漏
- 组件卸载后尝试 `setState` 造成 React 警告
- 不必要的网络请求

**修复建议**：使用 `useRef` 保存 interval ID，在 `useEffect` 的 cleanup 函数中 `clearInterval`。

---

#### BUG-005：联系表单提交是空操作

**位置**：[src/app/contact/page.tsx:16-19](src/app/contact/page.tsx)

**问题**：
```typescript
const handleSubmit = (e: React.FormEvent) => {
  e.preventDefault()
  alert('感谢您的咨询，我们会尽快联系您！')
  setFormData({ name: '', phone: '', company: '', interest: '', message: '' })
}
```
表单数据没有发送到任何后端 API，用户填写的咨询信息直接丢失了。

**影响**：用户提交的咨询请求实际无法送达公司。

**修复建议**：创建 `/api/contact` 路由，将表单数据存入数据库或发送邮件通知。

#### BUG-006：`createUser` 使用非空断言可能崩溃

**位置**：[src/lib/db.ts:80](src/lib/db.ts)

**问题**：
```typescript
const result = stmt.run(...)
return findUserByAccount(data.account)!
```
`findUserByAccount` 返回 `User | undefined`。如果 INSERT 因唯一约束冲突而失败（虽然前面有检查，但存在竞态条件），`!` 会将 `undefined` 强行断言为 `User`，导致后续访问 `user.id` 时抛出 `Cannot read properties of undefined`。

**修复建议**：检查返回值，为 null 时抛出明确错误。

---

#### BUG-007：Insights 页面 `useEffect` 缺少清理

**位置**：[src/app/insights/page.tsx:33](src/app/insights/page.tsx)

**问题**：
```typescript
useEffect(() => {
  setLoggedIn(isLoggedIn())
  fetchArticles().then(data => {
    setArticles(data)
    setLoading(false)
  })
}, [])
```
如果组件在 fetch 完成前卸载，`setArticles` 和 `setLoading` 会在已卸载的组件上调用，React 会输出警告。

**修复建议**：使用 AbortController 或在 effect 中设置 cleanup flag。

### 🟢 轻微（Code Quality / Best Practices）

#### BUG-008：`db.ts` 顶级 await / 同步初始化存在风险

**位置**：[src/lib/db.ts:9-16](src/lib/db.ts)

**问题**：`db.ts` 在模块加载时同步创建数据库目录和连接。在 Next.js 的 Turbopack 环境下，模块可能在构建时被加载，此时 `process.cwd()` 指向构建缓存目录而非项目根目录。

**实际观察**：当前构建能通过，说明 Next.js 处理了这个问题。但如果部署环境变化，可能导致数据库创建在错误位置。

**修复建议**：懒初始化数据库连接（在首次使用时创建），而不是在模块顶层。

---

#### BUG-009：`admin/articles/page.tsx` 中 `handlePaste` 和 `handleDrop` 缺少依赖

**位置**：[src/app/admin/articles/page.tsx:188-203, 205-212](src/app/admin/articles/page.tsx)

**问题**：`handlePaste` 和 `handleDrop` 使用了 `useCallback`，但依赖数组是 `[]`。它们内部调用的 `handleImageUpload` 函数在每次渲染时都会重新创建，所以这些 callback 捕获的是过时的闭包。

**修复建议**：将 `handleImageUpload` 也改为 `useCallback`，或者从依赖数组中移除空数组改用正确的依赖。

---

#### BUG-010：README.md 仍是 Next.js 脚手架默认内容

**位置**：[README.md](README.md)

**问题**：README 文件是 `create-next-app` 生成的默认模板，提到了 Geist 字体和 Vercel 部署，与程信霖公司网站完全无关。

## 六、代码质量总评

### 亮点 ✅
1. **组件抽象良好**：Button 和 Card 使用 `forwardRef` + `cva`（class-variance-authority），接口规范
2. **TypeScript 类型覆盖完整**：API 路由参数、数据库模型、组件 Props 都有类型定义
3. **Tailwind CSS v4 使用规范**：使用 `@theme inline` 定义设计令牌
4. **数据库操作使用 prepared statements**：防止 SQL 注入
5. **文章系统设计合理**：Markdown frontmatter + 内容分离，支持 Word 文档导入

### 待改进 ⚠️
1. **没有 API 层认证中间件**：所有 API 路由都需要自己检查认证，代码重复且易遗漏
2. **HTML ↔ Markdown 转换逻辑重复**：`admin/articles/page.tsx` 和 `api/articles/route.ts` 各有一套独立的 `htmlToMarkdown` 函数，应抽取到 `lib/`
3. **没有错误边界组件**：任何组件报错都会导致整个页面白屏
4. **没有 loading.tsx / error.tsx**：Next.js App Router 支持按路由的 loading 和 error 状态，但项目未使用
5. **`useEffect` 缺少清理逻辑**：多处 fetch 在组件卸载后仍会 setState
6. **数据库初始化在模块顶层**：不规范的懒加载模式
