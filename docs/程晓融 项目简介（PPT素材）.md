## 一、用户画像：我们为谁而做？

### 1.1 市场的断层

中国每年有 **超过 6000 万笔个人和企业贷款申请**，但绝大多数申请者面临一个共同的困境：

- 📌 **征信报告看不懂**——几十页的专业术语、表格、代码，普通人和中小企业主根本不知道自己的征信在银行眼里是好是坏
- 📌 **融资产品太多不知道怎么选**——银行、消费金融、信保机构、平台抵押……光是昆明就有几十款产品，每款的准入条件不同、利率不同、额度不同
- 📌 **盲目申请越申越差**——每次被拒都会在征信报告上留一道"硬查询"记录，查询太多反而影响后续申请
- 📌 **助贷中介良莠不齐**——传统线下助贷靠"人脑记产品"，推荐质量取决于中介的经验和良心
- 📌 **合规红线多**——融资咨询行业严禁"保证下款""内部渠道""包批"等承诺话术，但线下中介常常踩线

## 二、功能设计：一款"融资顾问的 AI 助手"

### 2.1 现有产品都在做什么？

市面上融资相关 AI 产品可以分为三大流派：

| 流派 | 代表产品 | 做什么 | 局限 |
|------|---------|--------|------|
| **B端风控流** | 百融云创、同盾科技、达观数据 | 为银行提供贷前尽调/征信解析/反欺诈 | 不面向借款端，中小企业用不了 |
| **C端导流流** | 微粒贷、借呗、京东金条 | 推荐自有贷款产品 | 只推自家产品，选择极其有限 |
| **信贷SaaS流** | 宇信科技、华夏银行"智合同"类 | 为银行提供信贷流程自动化 | 面向机构，不做借款端建议 |

**共同盲区**：没有一个产品站在**借款人**的角度，帮你分析"你的征信能匹配哪些产品、为什么、怎么改善"。

## 三、技术实现：怎么做到的？

### 3.1 技术架构概要

程晓融采用**"敏感数据本地化 + 推理能力云端化"**的混合架构：

```
用户上传征信报告（PDF/图片/企查查/银行流水/财报）
   → 本地 PaddleOCR 解析（OCR 引擎本地运行，不联网）
   → 结构化字段提取（年龄、逾期、查询次数、负债、资产……）
   → 本地 SQLite 产品库检索（8 大类几十款昆明真实产品）
   → 红绿灯规则引擎自动筛选（🟢绿灯/🟡黄灯/🔴红灯）
   → DeepSeek API 生成融资顾问报告（仅发送脱敏字段，不发送原文）
   → 合规过滤器（自动拦截银行名/产品名/承诺语）
   → Markdown 报告输出 + 前端渲染
```

### 3.2 核心技术难点

**难点一：本地 OCR 的高精度征信识别**

征信报告 PDF 是典型的复杂文档——表格嵌套、编码混杂、文字密集。程晓融使用 PaddleOCR（PP-OCRv4）本地部署，配合自研的 OCR 缓存机制（PDF 指纹校验，同一文件不重复跑 OCR），在保证隐私零外泄的同时，实现 15 页征信报告的 2 分钟级解析。

**难点二：自建本地产品库 + 规则引擎**

不依赖任何外部产品数据 API。自建 SQLite 产品库包含 8 张核心表（车抵贷、银行抵押、平台抵押、公积金贷、经营贷、税金贷、消费贷、信保贷），每款产品标注了利率、额度、年龄限制、征信查询要求、逾期容忍度、准入材料等关键字段。规则引擎从年龄、征信查询次数、逾期情况、信用卡使用率、授信机构数、公积金基数、企业经营年限、纳税等级等十几个维度进行自动化红绿灯分级。

**难点三：合规自动过滤系统**

融资咨询面临严格的合规红线。程晓融内置了三层合规防护：
- **第一层——Prompt 禁止**：AI 的 System Prompt 中明确禁止输出银行名、产品名、确定性承诺
- **第二层——黑名单过滤**：内置 30+ 银行命名实体黑名单 + 15+ 产品名称黑名单 + 禁止关键词（"包下款""内部渠道""无视征信""保证下款"），AI 输出逐一扫描
- **第三层——逾期兜底校验**：LLM 提取 `current_overdue` 后，再用正则从 OCR 原文二次校验——LLM 漏标"有"时强制修正。逾期触发一票否决时，强制输出黄色产品（待改善后可达标），并明确标注"暂不可申请"

**难点四：AI + 规则引擎混合架构**

产品推荐不是 AI"编"出来的。第二节核心推荐永远来自 SQLite 数据库 + 规则引擎筛选，AI 不得编造产品。AI 只写第 1 节资质快照和第 3 节差距分析——让 AI 做它擅长的自然语言叙事，让规则引擎做它擅长的事实性匹配。两者互不替代。

**难点五：多类型文档融合分析**

支持客户一次性上传多份文件：征信报告 PDF + 企查查报告 + 银行流水 Excel + 财务报表。系统自动识别文档类型，合并提取字段。个人和企业两套不同的提取模型——个人侧重征信查询/逾期/信用卡/公积金/职业，企业侧重经营年限/纳税/企业征信/流水/涉诉。

## 四、收费模式：按次付费，合作分账

### 4.1 为什么是"按次"？

市面上的融资服务收费模式：

| 模式 | 代表 | 问题 |
|------|------|------|
| 贷款抽佣 | 传统助贷中介 | 费用不透明，容易诱导高价产品 |
| 会员年费 | 法保网 | 年费门槛高，偶尔用一次不划算 |
| SaaS 年费 | 百融/同盾 | 面向机构，数十万/年，助贷门店用不起 |

**按次收费对借款人和助贷门店意味着什么？**

- 🔑 **零年费**：需要一次付一次，不需要全年订阅
- 🔑 **费用透明**：每次 20-50 元，客户和门店都算得清
- 🔑 **门店增效**：一个助贷经理一天人工只能服务 5-8 个客户，程晓融让他服务 30-50 个

### 4.2 定价结构

| 服务层级 | 服务内容 | 价格 |
|---------|---------|------|
| **免费版** | OCR 解析 + 结构化数据提取（不给产品推荐） | ¥0 |
| **标准版** | 完整融资体检报告（资质快照 + 产品推荐 + 差距分析 + 改善建议） | ¥20 / 次 |
| **企业版** | 标准版 + 企查查/流水/财报多文件融合分析 | ¥30 / 次 |

### 4.3 合作推广模式

| 合作模式 | 说明 | 适用场景 |
|---------|------|---------|
| **门店部署** | 助贷门店本地部署程晓融系统，按使用量结算 | 线下助贷门店 |
| **推广分账** | 推广方带来客户，消费金额按比例分账（建议 30-40%） | 商会、园区、代理记账公司 |

## 五、市场时机

### 5.1 为什么是现在？

1. **助贷行业合规化大趋势**：监管趋严，"保证下款""内部渠道"等话术风险越来越大，合规的 AI 融资顾问是刚需
2. **征信查询越来越频繁**：2024 年全国个人征信查询量超过 50 亿次，但绝大多数人看不懂自己的征信
3. **小微企业融资难持续**：5200 万中小微企业中，能从银行直接获得贷款的不到 20%，信息不对称是主因
4. **助贷门店效率瓶颈**：一个好中介一天最多服务 5-8 个客户，AI 可以把产能翻 5-10 倍
5. **本地产品库壁垒**：全国性平台给不出本地产品匹配——昆明的产品库和上海完全不同，这是天然的地域壁垒

### 5.2 竞争壁垒

| 壁垒类型 | 说明 |
|---------|------|
| **数据壁垒** | 昆明本地 8 大类几十款信贷产品库，标注关键字段，持续更新 |
| **合规壁垒** | 三层自动合规过滤 + 三条红线 + 银行/产品名黑名单，确保合规输出 |
| **隐私壁垒** | 本地 OCR + 仅传脱敏字段至 AI，满足金融监管"数据不出店"要求 |
| **规则引擎壁垒** | 基于 10+ 维度的红绿灯分级规则，不可被 LLM 绕过 |
| **多文档壁垒** | 征信+企查查+流水+财报四种文档融合分析，不是简单的 OCR |
